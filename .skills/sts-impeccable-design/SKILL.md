# STS Impeccable Design

1. Read `PRODUCT.md`, `DESIGN.md`, [design-tokens.md](references/design-tokens.md), [anti-ai-patterns.md](references/anti-ai-patterns.md), and [screen-review-checklist.md](references/screen-review-checklist.md).
2. Run the Impeccable command reference matching the request and scan the changed HTML/CSS with its detector.
3. Trace every new control to a geotechnical task, validation need, review need or proven navigation problem.
4. Keep operational density, alignment and stable dimensions. Use cards only for repeated records or framed tools.
5. Adapt structurally across desktop/tablet/phone and verify actual screenshots.
6. Preserve established components when they meet the task; remove inconsistency only inside the approved slice.

Failure behavior: reject polish that hides engineering context, weakens accessibility or introduces an unverified responsive regression.

Expected output: command findings, design decisions, changed tokens/components, detector result and desktop/tablet/phone evidence.

Provenance: Impeccable v3.9.1, root PRODUCT/DESIGN files, live baseline screenshots and the attached brownfield brief.
